# PLANO 03: IP e navegador nos JWTs + login que se renova sozinho
Status: concluído (validação manual pendente em make dev/VM)
Objetivo: o JWT de login e o ticket levam o IP e o navegador de quem pediu (para rastrear trapaça), e o login deixa de vencer para quem continua jogando, porque o cliente troca o token por um novo antes de vencer.
Fora do escopo: barrar token quando o IP/navegador muda; refresh token em cookie httpOnly; revogar sessão; fingerprint de navegador além do user-agent; prender backend/gameServer em 127.0.0.1 (quebraria os probes do k8s, ver Riscos); fechar o 443 da VM só para a Cloudflare.
Premissas e decisões: Clientes: não se aplica (repo sem `task clientes`; módulos tocados: backend, gameServer, client/web, k8s) · decisão do usuário: o IP entra no token só como registro, nunca para recusar · novas claims no login e no ticket: `ip`, `ua` (user-agent cortado em 256 caracteres) e `iat` (Unix) · leitura sempre com comma-ok: token antigo sem essas claims continua válido · regra única de IP nos dois módulos Go (`ClientIP(r)`, 10 linhas duplicadas; módulos separados): se a conexão vem de loopback (`net.ParseIP(host).IsLoopback()`, cobre `::1` e `::ffff:127.0.0.1`) E existe `X-Real-IP` que é um IP válido → usa o `X-Real-IP`; em qualquer outro caso usa o `RemoteAddr` sem porta; nunca lê `X-Forwarded-For` nem `CF-Connecting-IP` direto · por que isso cobre os caminhos reais: (1) produção pela Cloudflare: o nginx troca `$remote_addr` pelo `CF-Connecting-IP` (módulo realip, só quando a conexão vem de faixa da Cloudflare) e repassa como `X-Real-IP` pela loopback; (2) alguém batendo direto no 443 da VM com `CF-Connecting-IP` falso: não vem de faixa da Cloudflare, o realip ignora, e vale o IP real dele; (3) alguém batendo direto no 8088/4444: não é loopback, o `X-Real-IP` é ignorado e vale o IP real dele; (4) `make dev` na própria máquina: loopback sem cabeçalho → `127.0.0.1`; (5) amigos pela Radmin: falam direto com o 8088/4444 → `RemoteAddr` é o IP da Radmin (26.x), cabeçalho ignorado; (6) gameServer → backend (`/internal/*`): loopback sem cabeçalho → `127.0.0.1`, e o IP do jogador vai no corpo de `/internal/tickets` (confiável por causa da API key); (7) probes do k8s e smoke test: não são gravados · nginx da borda: no topo do snippet (contexto server, não afeta os outros sites da VM) `real_ip_header CF-Connecting-IP` + `include /etc/nginx/snippets/cloudflare-realip.conf`; em todos os `location` que vão para backend e gameServer (inclusive o upgrade do WebSocket) `proxy_set_header X-Real-IP $remote_addr` e `proxy_set_header CF-Connecting-IP ""` · faixas da Cloudflare: o script `cloudflare-realip.sh` baixa https://www.cloudflare.com/ips-v4 e /ips-v6, recusa lista vazia ou com linha que não é CIDR, grava o include, roda `nginx -t` e só então recarrega (se falhar, volta o arquivo anterior); roda no `edge-nginx.sh` e num timer systemd semanal; sem rede e sem arquivo anterior, aborta com mensagem · o `edge-nginx.sh` confere `nginx -V 2>&1 | grep -q http_realip_module` e aborta se o módulo faltar · IPv6: guardado como texto (até 45 caracteres); quem limita por IP usa o prefixo /64 · IP é pista, não identidade: CGNAT de celular, faculdade e amigos na mesma casa dividem IP, então nada no sistema bloqueia jogador logado por IP (o plano 05 limita por usuário) · Cloudflare "Pseudo IPv4" fica desligado (padrão); se ligar em modo "overwrite", o IP vira 240.x · o gameServer manda `ip` e `ua` do jogador no corpo de `/internal/tickets` (plano 02) e o backend grava no ticket; ausentes → vazios · novo `POST /auth/refresh` (grupo JWT): recarrega o usuário pelo `id` do token (401 se não existir), copia `username`/`email` do banco, recusa token temp, devolve `{token}` com `exp`, `iat`, `ip` e `ua` novos · regra do cliente: renova quando já passou da metade da vida (`now > iat + (exp - iat)/2`); sem `iat`, renova quando faltam menos de 12h para o `exp`; ao abrir o app e antes de `/newRoom` e `/getTicket`; uma renovação por vez (Promise reaproveitada); erro de rede mantém o token; 401 do refresh limpa a sessão e abre o login; token já vencido não é enviado · `JWT_REFRESH_MIDDLEWARE` (nada usa) sai de todos os arquivos · quem fica 24h sem abrir o jogo faz login de novo (aceito) · o agente não roda nada na VM: passos na VM ficam "(manual)" no aceite · Revisado em 2026-11-07: 13 correções aplicadas; análise de IP refeita a pedido do usuário (saiu o `BIND_ADDR`).
Pré-requisitos: plano 02 concluído (rota `/internal/tickets`, `ticketService`); acesso sudo do dono à VM para rodar `k8s/scripts/edge-nginx.sh`; referência de UI: nenhuma tela nova (a renovação é invisível; 401 reaproveita o modal de login existente)

## Riscos
- Prender os serviços em 127.0.0.1 quebraria o deploy: com `hostNetwork`, os probes `httpGet` do kubelet e os Services batem no IP do nó, não na loopback → não fazemos; quem fecha 8088/4444 para fora é a security list da Oracle (aceite manual)
- Cloudflare muda as faixas e o realip para de reconhecer → o timer semanal atualiza; enquanto não atualiza, jogadores daquela faixa aparecem com IP da Cloudflare (só registro, ninguém é bloqueado)
- Download das faixas falha ou volta lixo → o script valida CIDR, testa com `nginx -t` e mantém o arquivo anterior
- Token roubado renova para sempre enquanto o ladrão usar → decisão do usuário: sem teto de sessão; o refresh confere se o usuário existe; revogação fica para depois
- Relógio do cliente errado → atrasado renova tarde (o 401 abre o login), adiantado renova a cada chamada (barato); aceito
